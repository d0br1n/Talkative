# Milestone 3: The iPhone App — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An iPhone app with the CRT look that pairs with the voice side, holds a spoken conversation with the screen locked, shows the transcript and the voice-bar mark, and takes approvals. It is built without a Mac as an unsigned `.ipa` on GitHub Actions and installed with SideStore.

**Architecture:**
- The voice side (TypeScript) gains three phone messages, `settings`, `command` and `log`, without a protocol bump.
- `ios/TalkativeCore` is a Foundation-only Swift package holding everything worth testing: the protocol, the conversation reducer, the pairing client, the mark renderer, the band meter and the theme. It is tested on Linux in Docker and in CI.
- `ios/Talkative` is a thin SwiftUI app generated by XcodeGen. It turns LiveKit and audio-session events into store actions and draws the store's state. It is checked by a macOS CI build and on the owner's iPhone.

**Tech Stack:**
- Swift 6 toolchain, Swift 5 language mode, XCTest. Linux tests run in the `swift` Docker image.
- SwiftUI, iOS 17 minimum, LiveKit Swift SDK `client-sdk-swift` 2.20.0 (exact), XcodeGen 2.48.0.
- GitHub Actions: `ubuntu-latest` for `bun test` and `swift test`, `macos-26` (Xcode 26.x) for the app.
- Bun and TypeScript for the voice-side additions, as in milestone 2.

**Spec:** [`docs/specs/2026-11-25-ios-app-design.md`](../../specs/2026-11-25-ios-app-design.md). The background research is in [`research/ios-recon.md`](../../../research/ios-recon.md). The approved mockup is the Design canvas "Talkative iOS app" (the owner has the link); its values are copied into this plan, so implementers do not need it.

## Global Constraints

- **Look tokens, exactly** (spec 7.1):
  - dark: background `#0C0A07`, text `#FFE2A8`, accent `#FFC453`, muted `#D4B888`, border `#A88E60`, danger `#FF8A5C`;
  - light: background `#F5EEE0`, text `#1B1409`, accent `#A85200`, muted `#6E5B3E`, border `#8F7A5C`, danger `#B3261E`;
  - glow (dark only, on the mark, the wordmark and headings): four shadows, radius and RGBA: 2 pt `255,214,130,0.95`; 7 pt `255,170,40,0.80`; 18 pt `255,130,10,0.55`; 42 pt `255,110,0,0.35`. Body text gets no glow;
  - scanlines (dark only): 1 pt black at 18% every 3 pt. Vignette (dark only): black, 0% at 55% of the radius to 20% at the edge;
  - the app follows the system appearance.
- **Font:** JetBrains Mono Regular and Bold everywhere, bundled as TTF with `OFL.txt`. No SF fonts, no rounded speech bubbles, no blue.
- **Copy:** transcript labels `you ›` and `agent ›`; buttons are bracketed lowercase: `[ stop ]`, `[ type ]`, `[ approve ]`, `[ deny ]`, `[ connect ]`, `[ new conversation ]`, `[ leave ]`, `[ rejoin ]`, `[ unpair this phone ]`.
- **The wordmark** (`ios/Talkative/Resources/Logo/wordmark.txt`, 12 rows by 135 columns) heads every screen. The pair screen shows `lockup-mark.txt` stacked over the wordmark. These three files are the owner's logo; never edit them.
- **Accessibility:** text contrast at least 4.5:1 in both modes; touch targets at least 44 pt; the status line is real accessible text; the mark and the wordmark are images with the labels `Voice activity` and `Talkative`.
- **Reduce Motion:** the mark shows one still frame and the phosphor flicker stops. **Background:** no mark rendering while the app is not active.
- **Approvals happen only in the app.** Nothing spoken approves anything; no task adds a voice path to `decide`.
- **No GPL code in the app.** Dependencies: LiveKit (Apache 2.0) and its transitive packages only. Fonts: OFL.
- **No entitlements.** The entitlements file is empty. `Info.plist` carries `UIBackgroundModes: [audio]`, `NSMicrophoneUsageDescription` = `Talkative listens so you can talk with your agent.`, and `NSAppTransportSecurity.NSAllowsArbitraryLoads = true` (tailnet-only traffic, spec 5).
- **Bundle id** `io.github.d0br1n.talkative`, display name `Talkative`, version `0.3.0`, build number from `GITHUB_RUN_NUMBER` (1 locally).
- **Phone protocol stays at `PHONE_PROTOCOL = 1`.** New messages are additions; the TypeScript codec remains the source of truth and the Swift codec is tested against fixtures generated from it.
- **The voice side keeps its rules from milestone 2:** binds one address, never `0.0.0.0`; files under `~/.talkative` are mode 600.
- **Swift tests run only in Docker locally:** `scripts/swift-test` (Task 3). Never install Swift, Xcode tools or anything else on the host.
- **Owner gates:** pushing branches or tags, opening pull requests, and publishing releases each need the owner's yes in the coordinator's session. An implementer never pushes; the coordinator pushes `milestone-3/ios-app` for the iOS builds once the owner has said yes for that branch.

## Review Focus

1. **A model or effort change while the agent host restarts.** The agent host forgets a changed model when its process restarts. The voice side re-sends the phone's choice when a fresh agent host says `starting`, and the phone always sees the values in force. Test in Task 1.
2. **Partial or reordered streams.** A `delta` or `sentence` whose `blockStart` never came, a `speaking` for an unknown turn, or an `approvalDone` for an unknown id must not crash or drop text. Each creates or ignores what it must. Test in Task 7.
3. **A decision that never lands.** The owner taps `[ approve ]` while the link to the agent is down: the voice side answers with an `error`, the card must become tappable again, and the same id re-sent after a reconnect must not double the card or buzz again. Test in Task 7.
4. **A pairing token past its 30 days.** The app must say the pairing expired and offer the pair screen, not loop on failed joins. Test in Task 6 (expiry read from the token) and Task 7 (`✕ pairing expired`); Task 9 wires the refusal to `.expired` and stops retrying.
5. **Hostile or huge input from the phone.** A `log` line of 1 MB, a flood of `log` lines, control characters in a line, or a `settings` model outside `haiku|sonnet|opus` must not grow the log past 5 MB, block the voice side, or reach the agent's command line. Test in Tasks 1 and 2.

## Where this plan departs from the spec

1. **The iOS build also runs on pull requests that touch `ios/`.** Spec 5 keeps it off feature branches, but an app that is never built before merging can't be reviewed. Builds start only when the branch is pushed, which is owner-gated.
2. **The SideStore source is published with each release** (`releases/latest/download/source.json`), and only its template is committed. Committing a filled file would need a commit to `main` on every release.
3. **A third command, `quiet`,** is a barge-in from the phone: the voice stops and the agent carries on. Spec 6.2 maps the AirPods press to exactly this, and spec 6.1's `stop` also interrupts the agent.
4. **Four extra status lines:** `▲ waiting for you` (in the approved mockup), `… connecting`, `✕ not connected` and `✕ pairing expired`.
5. **Effort offers four values** (`default`, `low`, `medium`, `high`), the link's full set; the mockup showed three.
6. **A light-mode danger colour, `#B3261E`,** which the spec does not name; the dark one, `#FF8A5C`, is from the mockup.

### Task 2: Voice side: the phone log file

**Files:**
- Create: `src/voice/phone-log.ts`, `test/voice/phone-log.test.ts`
- Modify: `src/voice/service.ts`, `deploy/README.md` (one paragraph: where the phone log is and how to read it)

**Interfaces:**
- Consumes: `VoiceConversationOptions.phoneLog` (Task 1).
- Produces `class PhoneLog` in `src/voice/phone-log.ts`:
  - `constructor(o: { path: string; now?: () => number; maxLineBytes?: number; maxFileBytes?: number; perSecond?: number })`, defaults 2048, 5_000_000, 20.
  - `write(level: "info" | "error", text: string): void`. Synchronous append, never throws (a failed write goes to `console.error` once per minute at most).
  - Line format: `<ISO-8601 UTC time> <level> <text>\n`. In `text`, `\` becomes `\\`, newline `\n`, carriage return `\r`, and other C0 control characters `\xNN`. The whole line is cut to `maxLineBytes` on a UTF-8 boundary, ending with `…` when cut.
  - Rotation: before a write that would pass `maxFileBytes`, the file is renamed to `<path>.1` (replacing it) and a new file started. Both files are mode 600.
  - Rate: at most `perSecond` lines per wall-clock second; extra lines are counted and dropped, and the first write in a later second is preceded by `<time> info … dropped N lines`.
- `service.ts` passes `phoneLog: new PhoneLog({ path: join(homeDir(), "phone.log") })`.

- [ ] **Step 1: Write failing tests** in a temp `TALKATIVE_HOME`:
  - a line is written in the format, the file is mode 600;
  - a 1 MB text produces one line of at most 2048 bytes, ending `…`, valid UTF-8 (cut inside a multi-byte character);
  - `"a\nb\u0007"` is written as `a\nb\x07` on one line;
  - with `maxFileBytes: 200`, writing past it leaves `<path>.1` holding the earlier lines, a fresh file, and both mode 600;
  - 25 writes in the same second keep 20; a write one second later is preceded by `… dropped 5 lines`;
  - a path in a missing, read-only directory: `write` does not throw.

### Task 4: Band meter and mark mode

**Files:**
- Create: `ios/TalkativeCore/Sources/TalkativeCore/BandMeter.swift`, `ios/TalkativeCore/Sources/TalkativeCore/MarkMode.swift`, `ios/TalkativeCore/Tests/TalkativeCoreTests/BandMeterTests.swift`, `ios/TalkativeCore/Tests/TalkativeCoreTests/MarkModeTests.swift`

**Interfaces:**
- Consumes: `MarkRenderer.idleBars(t:level:)` (Task 3).
- Produces `final class BandMeter`:
  - `init(sampleRate: Double, bands: Int = 14)`.
  - `func process(_ samples: [Float]) -> [Double]` takes one mono buffer (any length from 256 to 4096) and returns `bands` levels in 0...1. It also sets `private(set) var rms: Double` (linear, of this buffer).
  - Method (the plan's decision, since the spec only says "one frequency band per bar"):
    - centres log-spaced from 150 Hz to 4000 Hz inclusive;
    - the power at each centre from a Goertzel filter over the Hann-windowed buffer, in dBFS;
    - tilt compensation `+3 dB × log2(centre / 500)`;
    - a shared running peak: the maximum compensated band level, falling 3 dB per second of audio processed, never below −50 dBFS;
    - `raw = clamp01((level − (peak − 30)) / 30)`;
    - output: rises at once to `raw`, falls with a 120 ms time constant.
- Produces `MarkMode.swift`:
  - `enum MarkMode: Equatable { case listening, thinking, speaking, down }`.
  - `static func select(connected: Bool, agent: AgentHealth, thinking: Bool, outputRMS: Double, micRMS: Double, micOn: Bool) -> MarkMode`. `AgentHealth` is `enum AgentHealth: String { case ready, restarting, down }`, defined here and reused by Task 5. Priority: `down` when not connected or the agent is down; `speaking` when `outputRMS > 0.01`; `listening` when the mic is on and `micRMS > 0.01`; `thinking` when `thinking`; otherwise `listening`.
  - `static func bars(mode: MarkMode, t: Double, output: [Double], mic: [Double]) -> [Double]`: speaking → `output`; listening → `mic`; thinking → `idleBars(t: t * 0.35, level: 0.22)`; down → `idleBars(t: 0, level: 0.1)`.

- [ ] **Step 1: Write failing tests.**
  - `BandMeter`, 48 kHz, 480-sample buffers:
    - 1 s of silence: every level ≤ 0.01 and `rms` = 0;
    - 0.5 s of a 1 kHz sine at −12 dBFS: the band whose centre is nearest 1 kHz is the largest and ≥ 0.9; `rms` within 0.005 of 0.177;
    - then 1 s of silence: every level ≤ 0.05;
    - white noise at −20 dBFS: at least 10 of 14 bands ≥ 0.3;
    - every output, for all of the above, is within 0...1 and the array has 14 entries.
  - `MarkMode`: one test per priority rule, plus `bars` for each mode (thinking equals `idleBars(t: t * 0.35, level: 0.22)`).

  - `enum PhoneCodec { static func decodeToPhone(_ data: Data) throws -> ToPhone; static func encode(_ m: FromPhone) throws -> Data; static func decodeFromPhone(_ data: Data) throws -> FromPhone; static func encode(_ m: ToPhone) throws -> Data }`. The last two exist for tests.
  - `struct PhoneProtocolError: Error, Equatable { let message: String }`. Rules match `src/shared/validate.ts`: malformed JSON, a non-object, an unknown `t`, a missing required field, or a field of the wrong type or outside its set throw; unknown extra fields are ignored. `encode` throws above `maxPhoneMessageBytes`. Encoders write keys sorted, omit absent optionals, and write `t` like TypeScript.
- Produces `RemoteLog.swift`:
  - `final class RemoteLog { init(capacity: Int = 200, maxLineBytes: Int = 2048); func add(_ level: LogLevel, _ text: String); func drain() -> [FromPhone] }`. Lines over `maxLineBytes` are cut on a character boundary. When full, the oldest line is dropped; `drain` then starts with `log(info, "… N earlier lines dropped")`. `drain` empties the buffer. Thread-safe with an `NSLock`.
