# sidetone technical map (crsmithdev/sidetone, MIT)

Read-only recon through `gh api`, against the default branch HEAD, 2026-11-24. Nothing was cloned or run. `src/` is about 10.3k lines of TS (no android/ and no docs/ beyond ADR titles were read). Spec section numbers ("11.3", "18.18") in comments refer to docs/spec.md, which I did NOT read.

## 1. Runtime and dependencies
- Bun only (`engines.bun >= 1.4.2`; tests use Bun fake timers). ESM, TS run directly (`bun src/main.ts <cmd>`). tsconfig: strict, bun-types, `allowImportingTsExtensions`.
- package.json deps: `@livekit/rtc-node ^0.13.35` (the bridge's room participant: native Rust FFI, so check ARM64 Linux prebuilds, UNVERIFIED), `livekit-server-sdk ^2.19.0` (only `AccessToken`), `livekit-client ^2.22.3` (served to the browser page as `/livekit-client.mjs`), `uqr ^0.1.3` (terminal QR). Dev: `@types/bun`, `playwright ^1.63.0`, `typescript ^5`. Scripts: `test` = `bun test`, `typecheck` = `bunx tsc --noEmit`. bun.lock is present.
- LiveKit server is NOT a dependency. `bun src/main.ts livekit` writes `~/.sidetone/livekit.yaml` and prints `docker run -d --name livekit --network host -v ~/.sidetone/livekit.yaml:/livekit.yaml livekit/livekit-server --config /livekit.yaml`. Generated config (`keys.ts livekitConfig`): `port: 7880`, `rtc.tcp_port 7881`, `port_range_start/end 50000-50019` (UDP), `node_ip: <advertiseHost>`, `use_external_ip: false`, `keys: {apiKey: apiSecret}`. Docs mention a TLS terminator in front of LiveKit for wss (docs/operating.md, not read).
- Web client (`client/index.html`, `client/decode.js`): imports `Room, RoomEvent, Track` from `/livekit-client.mjs`, POSTs `/pair`, stores `{token,url,room}` in `localStorage`, `new Room({audioCaptureDefaults:{echoCancellation,noiseSuppression,autoGainControl: true}})`, `room.connect(url, token)`, `setMicrophoneEnabled(true)`, control messages via `publishData(JSON, {reliable:true})` and `RoomEvent.DataReceived`. A browser needs HTTPS for the mic (Tailscale cert via `main.ts cert`).
- Deploy: `deploy/sidetone.service` (systemd user unit), plus `-card`, `-cert`, `-health`, `-recover` units/timers.

## 3. stream-json handling (session.ts, protocol.ts, config.ts)
- Argv = `claude` + `config.claudeArgs` + (Conversation) `--append-system-prompt <voiceInstruction> --permission-prompt-tool stdio --settings {"permissions":{"ask":[ASK_RULES]}}` + (spawnClaude) `--model <sonnet|opus|haiku>` [+ `--effort low|medium|high` unless default]. Default `claudeArgs`: `-p --verbose --input-format stream-json --output-format stream-json --include-partial-messages --replay-user-messages`. cwd = project dir; stdio all piped. Resume adds `--resume <id>` (+ `--fork-session --session-id <uuid>` for forks). No `--dangerously-skip-permissions` or `--permission-mode` is passed (ADR 0009 "permissive behind a gate" not read: how bypass is set is UNVERIFIED). Verified against claude 2.1.267/2.1.283.
- Turn in: one line of `{"type":"user","message":{"role":"user","content":"<text>"}}`. `ask(text)` = turn; `inject(text)` writes the same shape mid-turn (no interrupt) and tracks the `--replay-user-messages` echo.
- Parsed (`parseLine` -> `Event.kind`): `system/init` (init: sessionId, model), `system/status requesting`, `system/thinking_tokens`, `autocompact_state` (context window/threshold), `rate_limit_event` (5h/7d utilisation), `stream_event` (`text_delta` -> delta, `content_block_start/stop` -> blockStart/blockEnd, `message_start` -> messageStart+usage, `message_delta` -> messageEnd), `assistant`/`user` messages (text, `tool_use` -> toolStart, `tool_result` -> toolEnd, `parent_tool_use_id` kept), `user` with `isReplay` -> echo, `control_request can_use_tool` -> permission, `control_cancel_request` -> permissionCancel, `control_response` -> controlResponse, `result` -> result (text, total_cost_usd, usage, modelUsage window), anything with "compact" -> compaction, else `other` (still counts as activity).
- Session.handle: every event resets the supervisor's silence clock; delta/blockStart/blockEnd go to hooks (voice speaks them); toolStart/End feed supervisor and narrator; `result` resolves the pending `ask` promise (or `onUnprompted` for a background-task turn), tracks cost, context fill, rate limits.
- Interrupt: write `{"type":"control_request","request":{"subtype":"interrupt"}}`; if no recovery within `graceMs` (30 s) the supervisor restarts. Permission answer: `{"type":"control_response","response":{"subtype":"success","request_id":id,"response":{behavior:"allow",updatedInput}|{behavior:"deny",message}}}`.
- Supervisor defaults: `silenceMs 60000`, `ceilingMs 600000` (voice asks "continue"), `checkpointWindowMs 15000`, `graceMs 30000`, `compactionLimit 3`/5 min, `memoryRecycleBytes 4 GiB` (reads `/proc/<pid>/status`, Linux only).
- Resume/respawn: `sessionId` from init; `reload({model,effort})` respawns with `--resume id` after the running turn; `move(dir)` starts a fresh session in another project; fork when requests are slow (`forkSlowMs 1200`, `forkAfterRequests 3`); `restart(reason)` kills and starts fresh. Test seam: `Process` interface; `recorded()` tees a real run to NDJSON, replayed from `test/fixtures/stream-*.ndjson`.

## 4. Speech workers
- Subprocess per engine, spawned with `Bun.spawn([python, speech/<x>_worker.py, args...])`, stdin/stdout JSON lines, one reply per request, in order (`speech.ts Worker`; Python `worker.py` keeps the real stdout for the protocol and redirects the libraries' stdout to stderr). First line is `{"ready":true,...}`; replies carry `seconds`; failures `{"error":...}`.
- STT: request `{"wav": <path>[, "words":true]}` -> `{"text", ["words":[{word,start,end}]]}`. Whole utterance in, as a WAV file path on the shared filesystem (TS writes `encodeWav(samples, 48000)` to a scratch dir). faster-whisper, args `<model> <modelsDir> <vocabulary>`, `vad_filter=True`, `beam_size=1`, default `medium.en`. TS applies `sttCorrections`.
- TTS: request `{"text","wav":<path>,"voice":<name>}` -> `{"wav":<path>, ...times}`; reply gives file, not PCM. Ready line gives `sample_rate`. Piper (CPU), Kokoro (onnx, 54 voices, switch per request), Chatterbox (torch, voice clone from refs, ~20x slower than Kokoro). TS reads the WAV, nearest-neighbour resamples to 48 kHz and writes 20 ms frames. WAV reader takes 16-bit PCM only (`write_wav` forces `<i2`).
- Turn detector: `{"pcm": base64 int16 LE mono, "rate": multiple of 16000}` -> `{"probability","inference_ms"}`; ONNX Smart Turn v3.2 CPU, 8 s window, 4 intra-op threads, model path `~/.cache/sidetone/smart-turn/smart-turn-v3.2-cpu.onnx` (default `turnDetector: "shadow"`, so it logs but does not end turns; `"end"` ends turns at `turnEndProbability 0.8` with a `turnJoinMs 1500` retract window).
- `SpokenAhead` (speech.ts) synthesizes sentence N+1 while N plays; kept lines (fixed phrases like "Muted.") are pre-made and verified by STT into `~/.sidetone/spoken`.

## 5. The ear (ear.ts, audio.ts)
- Frames: Int16 mono at 48 kHz (`AudioStream(track,{sampleRate:48000,numChannels:1})`). Frame length is whatever rtc-node delivers (10 ms is its default, UNVERIFIED); the code only uses `frame.length/sampleRate`. Test harness uses 16 kHz.
- VAD: no neural VAD, pure RMS energy per frame (`level()`): speech if `>= speechLevel 0.02` for `speechOnsetMs 50`; pre-roll `onset+200 ms` kept. Whisper's own `vad_filter` is a second filter downstream.
- End of turn: quiet `>= endOfTurnPauseMs 1500` ends the utterance (`endedBy "pause"`). Held button (`hold`) disables the pause. Optionally Smart Turn can end it earlier (`"detector"`).
- Early transcription: at `earlyTranscribeMs 400` of quiet a tentative copy is transcribed at once; used if no more speech arrives (same `speechMs`), else discarded. Must be < `endOfTurnPauseMs` (checkConfig).
- Barge-in: energy `>= bargeInLevel 0.05` accumulating `>= bargeInMs 400`; dips shorter than `bargeInGapMs 200` do not reset it. On barge-in `to.stopSpeaking()` -> `mouth.hold()`; the speaker frame loop checks `cut()` per 20 ms frame and calls `source.clearQueue()`. Then `heard()` -> `discard` (new turn) or `resume`. `interruptOnSpeech` default false: speech mid-answer is refused with "I am still on the last one" unless the wake word is used; true injects into the running turn.
- Other guards: `minSpeechPeak 0.15` (too quiet dropped), `holdBackstopMs 10000`, echo-of-own-voice drop (`echoOf`, within `ECHO_AFTER_MS 1000`), mic-silence watch (`SILENCE_MS 30000` then `{kind:"rejoin"}`). Echo cancellation is delegated to the phone/browser (WebRTC AEC), not done server-side.

## 6. Control channel / protocol (messages.ts, channel.ts)
Transport: LiveKit data channel, JSON text, `publishData(..., {reliable:true})`, sent through `Outbound` (60 KB cap). Received via `RoomEvent.DataReceived`. Clients: web page, Android app, fake phone.
- Outgoing (bridge -> client): `heard`, `sentence{text,answer}`, `turn{number,text,costUsd,answer}`, `blockStart`, `delta{text,answer,block,seq}`, `blockEnd`, `narration{text,announce?}`, `error`, `history{turns:Kept[]}`, `rejoin`, `working{on}`, `starting{on}`, `settings{seq,settings}`, `speaking{text,answer?}`, `protocol{endTurn,apk?}`, `apk`, `screenshot{id,state}`, `show` (text/markdown inline, pdf by url), `setup` (phone audio setup).
- Incoming (client -> bridge): `said{text}`, `mic{on,hold?,release?}`, `voice{on}`, `setting{patch}`, `music{on}`, `quality`, `receive`, `screen`, `screenshot`, `crash`, `device`.
- Drift guard: `test/fixtures/messages.jsonl` (bridge-written) and `from-app.jsonl` (app-written) decoded by each client's tests.
- Not in this protocol: agent-side events (tool start/end, permission, checkpoint, result). Those are `SessionHooks` callbacks and `Agent` methods in-process; they are what Talkative's text WebSocket must carry.

## 7. Pairing and tokens
- `serve.ts pairingCode()`: three words from a 26-word list (17,576 codes), regenerated at each `serve` start, held in memory only, printed with a QR of `<origin>/#pair=<code>`. Client POSTs `/pair {code}`; `Pairing.pair` sleeps `min(wrong,20)*500 ms` per wrong guess; right code returns `{token,url,room}`.
- Token: `AccessToken(apiKey, apiSecret, {identity:"phone-<ts>", ttl:"<tokenDays*24>h"})` with grant `roomJoin, room, canPublish, canSubscribe, canPublishData` (`transport.ts tokenFor`). `tokenDays` default 30. Client keeps it in localStorage. Server stores no token list; revoking means changing the keys.
- Keys: `loadOrCreateKeys()` makes `{apiKey:"vb"+random, apiSecret: base64url(32 bytes)}` at `~/.sidetone/keys.json` (`SIDETONE_KEYS` overrides), chmod 600; config/env `LIVEKIT_API_KEY/SECRET/URL` override. The bridge joins as `bridge-<base36 ts>-<uuid8>` with a 24 h token. Unique identity matters (DUPLICATE_IDENTITY killed restarts). Bridge dials `ws://127.0.0.1:7880`; the phone gets `livekitPublicUrl` or `ws(s)://<advertiseHost>:7880`.
- Pairing is ADR 0005 "the pairing code is the boundary". No separate agent-side auth exists: Talkative must add auth for the agent WebSocket dial-out.

## 9. Things to change for ARM64 / CPU-only / not-the-author's-machine
- `speech/stt_worker.py`: hard-coded `WhisperModel(device="cuda", compute_type="float16")`. Needs `device="cpu", compute_type="int8"` (faster-whisper/ctranslate2 supports aarch64 CPU) and a smaller model than `medium.en`.
- `speech.ts cudaLibraryPath` + `LD_LIBRARY_PATH` injection, `Worker.start` env: drop. `speech/kokoro_worker.py`: `providers=["CUDAExecutionProvider","CPUExecutionProvider"]` and a "not the GPU" warning (CPU fallback already works). `chatterbox_worker.py`: `cuda if available else cpu`, but minutes per sentence on CPU; unusable, drop. Piper is the CPU engine (`piper-tts`; ARM64 wheel availability UNVERIFIED). `README`: "NVIDIA GPU and CUDA" requirement; `ttsEngine` default is `chatterbox`: change default.
- `config.ts` default paths: `pythonBin = ../.venv/bin/python` (relative to repo), `~/.sidetone/...` for models, kokoro/chatterbox venvs, sent/heard/spoken dirs, `~/.cache/sidetone/smart-turn/...onnx`, `~/.aleph/{repos.json,handoffs,jobs}`. All `homedir()`-based, no absolute `/home/<user>` paths found.
- Author-specific: `voiceInstruction` (addresses "Chris", mentions `sidetone.service`, `~/.sidetone/record.jsonl`, `bun .../main.ts show`), `sttVocabulary`/`sttCorrections` (aleph, Cloud Chamber, Beamline, Voiceover), `commands.ts` `switchProject` phrases, `project.ts` `/aleph:handoff` `/aleph:pickup`, `CLAUDE.md` aleph job instructions, `working.ts` and `news.ts` (aleph job news), wake word "sidetone".
- Linux-only bits: `/proc/<pid>/status` RSS (agent side, fine on laptop if Linux; macOS laptop would break, UNVERIFIED target OS), `tailscale` CLI shell-outs (`keys.ts`), systemd unit assumptions, `docker --network host`.
- `package.json` / `rtc-node`: native binary, confirm linux-arm64 prebuild exists for `@livekit/rtc-node` 0.13.x (UNVERIFIED). `scripts/fake-phone.ts` filters an "Nvidia Decoder" log line. Android app (`android/`, `src/apk.ts`, `device.ts`, `setup.ts`, `crash.ts`, `screen*.ts`) can be left out.
